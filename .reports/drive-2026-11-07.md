## What it covers

- `Epiphany::Application#build`: window, toolbar view, status page, header
  bar, menu button + page menu, notification container starting hidden.
- `BookmarksManager` / `Bookmark`: add, find by url, tag creation/indexing,
  bookmarks-by-tag, remove.
- `SearchEngineManager` / `SearchEngine`: default engine load, custom engine
  add, bang recognition and bang-search parsing.
- `PermissionsManager`: set/get a permission, permitted-origins listing.
- `TextEncodings`: built-in table loads, UTF-8 lookup.
- `SyncUtils`: hex and base64 round trips.
- `Link`: modifier-to-flags mapping. `Suggestion`: id/completion state.
- `Notification` + `NotificationContainer`: show, duplicate-drop, hide on
  empty — driven through the app's own real (already-realized) instances.
- `FloatingBar`: label update — same, through the app's real instance.
- `SearchEntry`: match counter, show/hide matches, clear-icon visibility,
  next-match firing on activate.
- `TitleWidget` mixin: secure?/icon_name contract.
- `ShortcutsDialog`: opened through the real `app.shortcuts` action.
- `app.quit` action: records window geometry into `Settings::STATE` before
  quitting — fired last, since it ends the app.

Not covered because not yet wired into the application: the browsing window
proper (`src/ephy-window.c` and everything under it) is not ported yet —
`Application#status_page` says so truthfully. `BookmarksExport`,
`BookmarksImport`, `OpensearchEngine.load_from_link` / `SearchEngine#fetch`
(network I/O) and `SyncUtils`' Firefox-account flow are not exercised; they
need either a real network or fixture data this round didn't set up.

## Bugs found and fixed in the *test*, not the port

- `SearchEngineManager.new(settings:)` and `TextEncodings.new(settings:)`
  want a `Settings::Schema` (what `Settings.main` / `Settings.state` hand
  out), not a bare `Settings` instance. First draft of the drive script
  passed a `Settings` instance and got `NoMethodError: undefined method
  'get_string'` / `'get_strv'`.
- `BookmarksManager#add_bookmark` does not index a new bookmark's tags into
  `@tags` — confirmed this matches upstream:
  `ephy_bookmarks_manager_add_bookmark_internal` (src/bookmarks/
  ephy-bookmarks-manager.c) doesn't either; only the sync-merge path
  (`create_tags_from`) does. The drive script now calls `create_tag`
  explicitly, as the real UI would.
- `SearchEngineManager#parse_bang_search` returns the built search-address
  string, not `[query, engine]` — first draft asserted the wrong shape.

## Real gap found, left failing/noted rather than worked around

The dev-shell banner's spec command —

    ruby -e 'require "rspec/core"; exit RSpec::Core::Runner.run(["--format", "progress", "--require", "spec_helper", "spec"])'

— fails to load: `spec/spec_helper.rb` requires `kettle/test/rspec`, which
`nix/Gemfile` deliberately excludes (its header comment says that stack
belongs to the dev-only root `Gemfile`, not the packaged runtime). This is a
pre-existing environment/packaging gap, not something this round's code
touched, and `spec/` holds no example files yet (only `spec_helper.rb` and
`README.md`), so no test content is lost by it — but "run the specs" as the
banner documents it does not currently work inside this flake's devShell.
No ruby-gnome binding gaps were hit in this round.
